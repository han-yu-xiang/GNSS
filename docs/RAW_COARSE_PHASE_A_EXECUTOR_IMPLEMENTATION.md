## 4. State machine and human gate

The state progression is intentionally one-way:

```text
manifest hash check
        |
        v
validation-only / preflight
        |
        +--> rejected
        |
        v
G16 EXECUTION_ELIGIBLE
        |
        v
human supplies --execute --confirm-phase-a
        |
        v
G16 task completes or fails
        |
        v
independent G16 QA PASS receipt
        |
        v
G25 EXECUTION_ELIGIBLE
        |
        v
human separately confirms G25 execution
```

Rules encoded in the executor:

- validation-only is the default;
- `--confirm-phase-a` is invalid without `--execute`;
- G16 is the only task allowed to execute before a QA receipt;
- G25 requires a separate QA receipt with the exact G16 manifest SHA and completed zero-exit attestations;
- G11 and any task not in the two frozen Phase-A manifests are rejected;
- the executor never automatically starts G25 after G16;
- the executor never automatically declares the research success gates passed;
- no resume and no overwrite are supported.

The independent G16 QA receipt is expected at:

`dataset_generation_logs/sampling_validation/batch_sampled_v1_2_phase_a_qa/g16_qa_pass.json`

It must be produced by an independent post-run QA process, not synthesized by this executor. It must attest the exact G16 manifest SHA, `qa_status=PASS`, `executor_status=completed`, `exit_code=0`, `raw_read_status=ok`, and complete outputs.

`dataset_generation_logs/sampling_validation/batch_sampled_v1_2_phase_a_outputs_20260812/Phase-A1_F1023_V70_D0120_P7_G16_ch1`

The global lock is:

`dataset_generation_logs/sampling_validation/batch_sampled_v1_2_phase_a_execution.lock`

It is acquired atomically with exclusive file creation and released only after the parent executor writes its receipt. A second task cannot run concurrently. A pre-existing lock is a hard rejection; it is not silently deleted as stale.

## 7. Execution receipt and failure handling

The parent executor starts a private worker using the frozen absolute Python executable. It owns the global lock, monitors progress, and keeps the output directory if the worker fails.

The worker writes task artifacts only in the manifest output directory. Expected artifacts include:

- `coarse_parameter.json` and `coarse_parameter.sha256`;
- `selection_freeze.json`;
- `input_receipt.json`;
- `progress.jsonl` and chunk manifest;
- one coarse/promotion/component/cost/run manifest set per frozen profile;
- post-freeze coverage replay files;
- task `run_manifest.json`.

The parent writes `execution_receipt.json` with:

- manifest, parameter, kernel, pipeline and prototype hashes;
- Python executable path and SHA-256;
- Python/NumPy/SciPy/OpenBLAS receipt;
- UTC start/end and exit code;
- stdout/stderr log paths;
- raw bytes, chunks and available window-progress counters;
- output file list and SHA-256 for each output;
- status and error;
- `resume=false`, `automatic_next_task=false`, and `gold_labels_used_for_selection=false`.

On non-zero exit, exception, KeyboardInterrupt, stall timeout, or total timeout, status is `failed` or `interrupted`, a receipt is retained, and partial output is preserved. The executor does not delete, resume, truncate, or launch another task.

The current monitoring defaults are a 30-minute no-file-progress stall timeout and a 48-hour total timeout. They are safety limits, not algorithm parameters.
